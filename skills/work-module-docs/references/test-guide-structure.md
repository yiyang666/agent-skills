# TEST_GUIDE 结构规范

## 目录

1. 读者与目标
2. 推荐章节
3. 测试场景写法
4. 完成标准

## 1. 读者与目标

TEST_GUIDE 面向测试部和不熟悉实现细节的协作者。重点是把环境准备、模块启停、日志观察和基础验证说清楚，不要求采用专业测试管理术语，也不替代正式测试用例平台。

## 2. 推荐章节

### 2.1 功能与测试范围

用简短语言说明本次要测的能力、明确不在范围内的能力，以及适用代码版本、分支或构建产物。

### 2.2 环境准备

列出：

- 操作系统、硬件/机器人/设备、运行时和依赖版本。
- 关联服务、网络、端口、账号权限和测试数据。
- 配置文件位置与需要修改的非敏感项。
- 安装、构建或制品获取命令。

无法确认的环境项标为 `待确认`。

### 2.3 启动、停止与状态检查

按实际顺序给出依赖服务和目标模块的启动命令。每一步说明看到什么现象才算启动成功，并提供安全停止与清理方法。

### 2.4 日志与常用命令

至少说明日志位置或查看方式、关键成功/失败关键词、进程/端口/Topic/容器状态检查命令。命令按运行位置分组，例如宿主机、容器内、机器人端。

### 2.5 测试场景

每个场景包含：

- 场景名称与目的。
- 前置条件。
- 操作步骤。
- 预期结果。
- 日志、接口、UI、Topic 或设备状态观察点。
- 清理/恢复动作。

优先选择业务上容易执行且结果可观察的场景，不写只有开发者才能理解的内部断言。

### 2.6 常见问题

按“现象—检查方法—可能原因—恢复建议”组织。只写代码、配置或真实经验可以支持的问题。

### 2.7 测试反馈信息

列出测试部反馈问题时应附带的信息，例如版本、配置差异、复现步骤、时间点、完整日志、截图/录屏和设备状态。

## 3. 测试场景写法

推荐使用统一表格：

| 编号 | 场景 | 前置条件 | 操作步骤 | 预期结果 | 观察点 | 清理 |
|---|---|---|---|---|---|---|

步骤较长时，每个场景单独成节，并在总表中保留索引。

至少覆盖正常路径、边界条件和常见异常。模块具备断线重连、幂等、状态恢复或并发控制时，应增加相应场景。

未实际执行的场景必须标注“待执行”，不能写“已通过”。

## 4. 完成标准

- 测试人员无需阅读源码即可启动、停止并查看日志。
- 每个场景都有明确、可观察的预期结果。
- README 与 TEST_GUIDE 中相同命令和参数一致。
- 测试不会默认连接生产环境、清理真实数据或控制未授权设备。
