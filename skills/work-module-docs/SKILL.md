# 工作模块文档

**只需读本文 + 对应模板**（`assets/README.template.md` / `assets/TEST_GUIDE.template.md`），不必再读其他 reference 文件。

## 文档分工

| 文档 | 读者 | 写什么 |
| --- | --- | --- |
| `README.md` | 开发者 | 定位、架构、时序、接口设计、配置与故障定位 |
| `TEST_GUIDE.md` | 测试部 | 测什么、话题/命令、启停、场景表；**自洽，不必翻 README** |

## 输入

- **必需**：模块路径
- **可选**：用户给出的「必测功能清单」——有则按清单生成场景；无则从代码归纳并在交付时列出
- **已有文档**：先读再改，保留仍正确的用户手写内容，无提示不覆盖

## 工作流

1. **定范围**：入口、构建方式、配置文件、上下游依赖
2. **收证据**（见下表，禁止臆造）
3. **写 README**：按 `assets/README.template.md`，删空节
4. **写 TEST_GUIDE**：按 `assets/TEST_GUIDE.template.md`，删空节
5. **校验**：用文末清单；交付时说明依据文件与仍待确认项

### 证据来源

| 需要的信息 | 优先查找位置 |
| --- | --- |
| Topic / 消息 / RPC | `advertise`/`subscribe`、Publisher/Subscriber、`.msg`/IDL、配置 yaml |
| 话题名、频率、类型 ID | 模块 `config/**`、`*_config.yaml`、环境变量 |
| 启停与进程名 | 入口 `main`、systemd/守护脚本、`robot_control` 等运维 CLI |
| 诊断命令 | 仓库内工具 README（如 `lyostopic`）、模块已有文档 |
| 版本策略 | 用户说明、`syskit info` 等整机命令；**区分「版本基线」与「部署路径」** |
| 日志关键词 | `lyos_log_*`、logger 调用、现有 TEST_GUIDE |

**待确认**：仅当上述检索后仍无法确定；须写明缺什么证据。仓库已有工具文档时，**不得**对命令语法写「待确认」。

## README 要求

- 模块边界、至少一张与代码一致的 Mermaid 架构图；有跨组件交互则加时序图
- 接口写**边界处**重要项（Topic/HTTP/设备 I/O），不抄全部内部函数
- 配置、启动、错误处理、并发/状态（若有）、关键设计决策
- 小型库可合并章节；无部署职责不写伪造部署节
- 文末链到 `TEST_GUIDE.md`

## TEST_GUIDE 要求（重点）

测试部应能：**不读源码 → 启停 → 用命令验证 → 判 pass/fail**。

### 必选章节（模板已编号，可合并表述，不可缺实质）

1. 功能与测试范围（含不在范围）
2. 测试基线（模块、产品/平台、**版本**、配置模板路径）
3. **话题与接口**（或等价对外接口表：方向、名称、消息类型、频率/触发、关键字段）
4. 环境准备
5. 启停与运行判据
6. **测试命令速查**（可复制命令块：查接口、测频率、发控制、进程/网络/日志）
7. 测试场景表
8. 常见问题
9. 测试反馈清单

### 写作规则

- **简洁**：表格优先；同一事实不重复三遍
- **可执行**：「本次覆盖」的每个功能 ≥ 1 条具体观察命令或量化现象（如 `lyostopic hz …` ≈ N Hz）
- **场景表**：观察点列写**命令 + 预期**，不要只写「观察点云话题」
- **多实例/多产品**：用配置差异表（如 front/rear/top），话题名以 yaml 为准
- 未执行的场景：文首或场景处标「待执行」，不写「已通过」
- 不写凭证；不默认连生产或破坏性操作

### 场景覆盖（默认至少 3 条，用户清单优先）

| 类型 | 示例 |
| --- | --- |
| 正常 | 启动 + 核心数据/接口可用 |
| 边界 | 配置开关、可选功能开/关 |
| 异常 | 依赖不可用、错误配置、断连恢复（若模块有） |

用户提供的功能清单 **1 功能 ≈ 1 场景（T01…）** 即可，不必凑复杂用例。

### 常见模块形态（举例，按实际模块选用）

**LYOS 驱动类**（lidar/camera/app 等）：配置在 `config/driver/<产品>/<平台>/`；常用 `lyostopic list|echo|hz|pub`、`robot_control stop <进程名>`、`syskit info`；status/control 话题可能多实例共用，靠 `sensor_type` 区分。

**纯库 / 无 Topic**：§3 改为「公开 API / CLI / 文件接口」；§6 改为对应调用示例。

## 校验清单（交付前自检）

**README**：概述、架构图、边界接口、配置/启动、无占位符/伪造/凭证。

**TEST_GUIDE**：范围、基线、**接口表**、**命令速查**、≥3 场景且观察点可执行、待执行标注正确。

**一致性**：进程名、路径、话题名、启动参数在两份文档中一致。

## 更新原则

- 以当前代码与配置为准；只改受影响的章节
- README 与 TEST_GUIDE 命令/路径保持一致
- Mermaid 节点名稳定、简短
