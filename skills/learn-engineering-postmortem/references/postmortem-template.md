# 工程复盘文档模板

按需删减小节，但尽量保留「背景 → 方案 → 原理 → 发散」。

```markdown
# <一句话主题：场景 + 手段>

> 场景：…  
> 用途：知识沉淀 / 设计复盘 / 面试材料  
> 关键词：…

## 1. 问题背景

### 1.1 现象
- 必现/偶现条件
- 用户可感知后果（尤其安全相关）

### 1.2 旧架构为何失败
- 数据流/控制流简图
- 2–5 条可验证缺陷（对应代码或协议行为）

### 1.3 易混淆点（可选）
- 哪些是主因，哪些只是强化因素

## 2. 解决方案总览
- 目标行为（例如：失联后 ≤X ms 进入安全态）
- 分层表：手段 / 解决什么 / 优先级

## 3. 关键手段：原理与解决的问题
对每一项：
- **原理**（机制怎么转）
- **解决了什么**（对应第 1 节哪条缺陷）
- **面试一句话**

## 4. 如何形成闭环（可选）
一张从输入到执行器的时序/租约图。

## 5. 发散：后续哪些设计也该这样考虑
写成可迁移检查项，例如：
- 保持型控制是否有租约？
- 事件型 vs 状态型是否用错协议？
- 不可靠信道是否有序号/幂等？
- 是否有纵深超时？上游是否会刷新陈旧值？

## 6. 面试表达模板（可选，60–90 秒）
背景 → 根因 → 方案 → 本质抽象 → 迁移经验

## 7. 参数与边界备忘（可选）
关键阈值、接口、覆盖范围、明确暂缓项
```
